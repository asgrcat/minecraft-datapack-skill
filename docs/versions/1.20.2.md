# Java Edition 1.20.2

data pack format 18。function macro、行継続、overlayを正式導入します。

## function/command

- 行末の `\` で次行を連結
- `$` macro line と `$(variable)`
- `function <id> <compound>` / `function <id> with <data source> [path]`
- `/random value|roll <range> [sequence]` と sequence reset
- **正式リリースでは** `execute if|unless function` と `return run` は削除された状態。1.20.3で再導入

## `pack.mcmeta`

- `supported_formats`。`pack_format` は引き続き必須で範囲内
- `overlays.entries[]` の `formats` と `directory`

## NBT/JSON

- mob effect NBTを snake_case + namespaced string IDへ
- `CustomPotionEffects→custom_potion_effects`, `ActiveEffects→active_effects` 等
- loot function `sequence`、predicate `all_of` のinline配列
- block/fluid state property matcherの値は数値/booleanでもJSON string必須
- scoreboard slot `belowName→below_name`

## JSONパラメータ差分

- **item**: mob effect 関連 NBT を snake_case と namespaced ID に移行し、例として `CustomPotionEffects` を `custom_potion_effects`、`ActiveEffects` を `active_effects` に変更。旧キーを使う item／entity NBT は書き換える。predicate の `all_of` はインライン配列形式へ移行した。
- **dimension/worldgen**: 1.20.1 の定義を継承し、この系統固有のルート変更はない。block／fluid state matcher の property 値は JSON 文字列に統一されたため、worldgen 条件で数値や真偽値を直接指定していた場合は引用符を付ける。
- **enchantment**: 固定レジストリのまま 1.20.1 を継承し、この版固有の JSON 差分はない。
- **variant**: `type_specific` を含む entity predicate は 1.20.1 を継承し、この版固有の variant レジストリ追加はない。
- **predicate**: `all_of` は明示objectだけでなく、typeを省いたcondition配列でも表現可能になった。block／fluid state property matcherは数値・booleanを受理しなくなり全値をJSON stringで書くため、1.20.1の非文字列値は書き換える。
- **advancement**: rootとtrigger集合は1.20.1を継承する。trigger内のloot condition listでも `all_of` のinline配列が使える一方、block／fluid state property値は文字列必須となるためnested conditionを再検証する。
- **loot_table**: sub-functionを順に実行する `sequence` loot functionを追加し、function list自体もtypeなし配列で同じ合成を表せる。`all_of` conditionのinline配列を追加し、block／fluid state matcherのproperty値を文字列へ限定した。
- **recipe**: recipe typeとfieldは1.20.1を継承し、このカテゴリ固有の追加・変更・削除はない。mob effect NBTやloot `sequence` の変更をrecipe schemaへ誤適用しない。
- **item_modifier**: `sequence` functionを追加し、`functions` 配列またはitem modifier rootのinline配列でsub-functionを順次適用できる。conditionのinline `all_of` とstate値文字列化も適用されるため1.20.1定義を再検証する。

## AI 生成規則

- 開発snapshotの `return run` 例を正式1.20.2へ出力しない
- macro変数を型安全と見なさず、外部文字列をcommand位置へ挿入しない
- overlayはresource削除機能ではなくadd/replaceとして設計する
