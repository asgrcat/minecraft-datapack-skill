# Java Edition 26.3 Snapshot 4

data pack format 111.0。loot／predicate／advancementの参照形式を統一する大規模なschema変更です。

## metadata

```json
{
  "pack": {
    "description": "26.3-snapshot-4 data pack",
    "min_format": [111, 0],
    "max_format": [111, 0]
  }
}
```

## コマンド

- `/spreadplayers` の安全な着地点判定に `#entities_can_teleport_to` block tagを使用
- sign text内のcommand／click eventは既定で実行されない

## JSON/NBT/registry

- advancement、item modifier、loot table、number provider、predicate、recipe、slot sourceのfieldでregistry ID／tag／inline値を統一的に受付
- predicateのdiscriminatorを `condition` から `type` へrenameし、`minecraft:reference`を削除
- loot functionのdiscriminatorを `function` から `type` へrename
- loot entry/functionの `conditions` を単一の `condition` へrenameし、暗黙AND配列を削除
- loot entryの `functions` を `modifier` へrename
- `minecraft:match_block` predicateを追加し、`block_state_property`を削除
- sign／hanging signに `allow_op_features` を追加。新規signでは既定 `false`
- `minecraft:cooking_fuel`、`brewing_fuel`、`sign_text_front`、`sign_text_back`、`waxed`、`cushion/color`、`villager_food`、`mob_visibility` item componentを追加
- `natural_mob_spawns` と `creature_world_gen_spawn_probability` environment attributeを追加
- `minecraft:container_process` loot table typeを追加
- advancement triggerのpredicate／loot table／recipe等のfieldをregistry参照対応へ変更し、一部を複数形へrename

## 互換性

110.0のpredicate、loot table、item modifier、advancementを一括変換してからreloadします。`reference` wrapperをID文字列へ置換するだけでなく、discriminator、複数形field、暗黙AND配列も同時に移行してください。

## JSONパラメータ差分

- **item**: `cooking_fuel`、`brewing_fuel`、sign text／waxed、cushion color、villager food、`mob_visibility`を追加。sign関連componentのblock entity交換を拡張
- **dimension/worldgen**: mob spawn用environment attribute 2種を追加し、ambient particlesへ`append` modifierとtimeline補間を追加
- **enchantment**: nested predicate／number provider／item modifier参照を111.0の直接ID形式へ移行
- **variant**: 26.3-snapshot-3を継承。固有のvariant registry追加・削除なし
- **predicate**: discriminatorを`type`へrenameし、`reference`を削除。`match_block`を追加し`block_state_property`を削除。複合条件は明示object化
- **advancement**: trigger条件でpredicate IDを受付。loot table／recipe等のfieldを複数形・holder set対応へ変更し、暗黙condition配列を削除
- **loot_table**: entry/functionの`conditions`→`condition`、entryの`functions`→`modifier`、functionの`function`→`type`を適用。registry ID／tag参照を拡大
- **recipe**: recipe holder参照を単一ID／list／tagで扱えるfieldを追加。個別serializer集合は前スナップショットを継承
- **item_modifier**: function discriminatorを`type`へrenameし、`conditions`を`condition`へ変更。`reference`を削除して直接ID参照へ移行

## AI 生成規則

- predicateで `condition` discriminatorや `minecraft:reference`を出力しない
- loot functionで `function` discriminatorを出力しない
- condition配列を暗黙ANDとして出力せず、`minecraft:all_of`を明示する
- sign command実行が必要な場合だけ `allow_op_features: true` を明示し、安全上の影響を説明する
- holder set対応fieldと単一ID限定fieldを公式JARのcodecで区別する
- 実験world以外へ適用しない
