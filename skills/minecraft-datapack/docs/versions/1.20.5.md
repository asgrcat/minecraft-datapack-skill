# Java Edition 1.20.5

data pack format 41。item stack の自由形式 NBT を structured data components へ置換した最大級の破壊的変更です。

## item command

```mcfunction
# 1.20.4以前
give @s minecraft:stick{foo:"bar"}

# 1.20.5
give @s minecraft:stick[minecraft:custom_data={foo:"bar"}]
```

- item stack は `id`, `count`, `components` の構造へ
- item predicate は component完全一致、sub-predicate、否定、選択、countを扱う
- `/execute if|unless items <block|entity> <slots> <item_predicate>`
- `/transfer <hostname> [port] [players]`
- `/attribute` operation名を `add_value|add_multiplied_base|add_multiplied_total`

## JSON

- recipe resultにcomponents
- item predicateの旧 `tag`, `durability`, `potions`, `nbt`, `enchantments` fieldsを削除し `items`, `components`, `predicates` へ
- loot `set_nbt→set_custom_data`, `copy_nbt→copy_custom_data`
- loot function `set_components`, `copy_components`, `modify_contents`
- `banner_pattern`, `wolf_variant` registry
- worldgen number providerの余分な `value` wrapperを削除

## 互換性

world内itemはDataFixされる場合がありますが、pack内mcfunction/JSONは自動変換されません。1.20.4以前との共通化はitemを触る全fileを分けます。

## JSONパラメータ差分

- **item**: アイテムスタックを `{id,count,components}` と item component patch に移行し、コマンド表記も `[component=...]` となった。item predicate の旧 `tag`、`durability`、`potions`、`nbt`、`enchantments` などを削除して `items`、`components`、`predicates` に置換し、recipe result には `components` を追加。loot function の `set_nbt`／`copy_nbt` も改名・置換されたため、旧形式は自動互換ではなく全面移行が必要。
- **dimension/worldgen**: worldgen number provider から冗長な `value` ラッパーを削除。該当 provider を直接値または provider object に直す。dimension type のルート項目は 1.20.4 を継承する。
- **enchantment**: definition自体は固定レジストリのままだが、表示順を指定する`tags/enchantments/tooltip_order.json`を追加。アイテム上のenchantment判定は旧`enchantments` fieldではなくitem component predicateへ移行する。
- **variant**: データ駆動の `wolf_variant` レジストリを追加し、`data/<namespace>/wolf_variant/<id>.json` で定義する。1.20.4 以前にはこの registry がなく、同じ JSON は読み込めない。
- **predicate**: item predicateの旧 `tag`／`durability`／`potions`／`nbt`／`enchantments` 等を削除し、`items`、完全一致の `components`、component sub-predicateの `predicates` へ全面移行。block／fluid／location predicateは単数fieldと旧 `tag` を複数形fieldへ統合し、entity predicateへ `slots` を追加したため1.20.4形式は非互換。
- **advancement**: `display.icon` を旧 `{item,nbt}` からitem stack `{id,count,components}` へ変更し、全trigger内のitem／block／fluid／location／entity predicateも新形式へ移行。`default_block_use`、`any_block_use`、`crafter_recipe_crafted`、`fall_after_explosion` を追加し、`item_used_on_block` はitem使用が成功した時だけ発火する。
- **loot_table**: item stack／predicateをcomponents形式へ移行。`loot_table` entryは `value` にIDまたはinline tableを取り、`equipment` typeと `storage` number providerを追加。function listのnested listを禁止し、`set_contents`、`set_name`、`set_attributes`、`set_lore` 等も変更されたため旧tableは全面再検証する。
- **recipe**: `crafting_shaped`、`crafting_shapeless`、`stonecutting`、`smithing_transform` のresultがcomponentsを受理。smelting／blasting／smoking／campfire_cookingのresultは文字列から `id` を持つitem stack objectへ変更されcountは持たず、旧result表現は非互換。
- **item_modifier**: `set_nbt`／`copy_nbt` を `set_custom_data`／`copy_custom_data` へrenameし、`set_components`、`copy_components`、`modify_contents` 等を追加。`set_contents` の `type` を削除して必須 `component` を追加し、nested function listも禁止されたため1.20.4 modifierは機械的流用できない。

## AI 生成規則

- 旧 `{tag}` item suffixを出力しない
- arbitrary custom dataは `minecraft:custom_data`、標準機能は対応するtyped componentへ
- component ID/fieldを1.20.5のregistry reportで制限する
